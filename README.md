# ИС «Школа изучения итальянского языка»

Веб-приложение на **Django 6 + PostgreSQL 18** по лабораторным работам № 1–9, вариант 9.
Архитектура соответствует ЛР 8: браузер → сервер приложений (Django, gunicorn) → СУБД PostgreSQL.

## Запуск

Всё в Docker (база и приложение):

```bash
cp .env.example .env
docker compose up -d --build      # http://127.0.0.1:8000
```

Для разработки — база в Docker, Django локально:

```bash
cp .env.example .env
docker compose up -d db
uv sync
uv run python manage.py migrate
uv run python manage.py seed_demo  # тестовые данные и пользователи
uv run python manage.py runserver  # http://127.0.0.1:8000
```

Тесты: `uv run python manage.py test school` (нужна запущенная БД).

## Что реализовано

| Требование из лаб        | Реализация                                                                                                                                                                                                                                                                                                             |
|--------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| ЛР 1 — функции ТЗ        | справочники (ученики, преподаватели, курсы A1–C2, аудитории), зачисление в группу, расписание, учёт оплат и долгов, отчёты, роли администратор / преподаватель / ученик                                                                                                                                                |
| ЛР 1 — надёжность        | проверка вводимых данных, резервная копия (меню пользователя → «Резервная копия БД»)                                                                                                                                                                                                                                   |
| ЛР 3–4 — модель данных   | PostgreSQL, 8 таблиц `student`, `teacher`, `course`, `classroom`, `study_group`, `enrollment`, `payment`, `lesson` — те же имена таблиц и столбцов (`student_id`, `pay_date`, ...), что в физической модели; связи 1:N, внешние ключи, CHECK и UNIQUE                                                                  |
| ЛР 8 — архитектура       | трёхуровневая: браузер → Django (gunicorn) → PostgreSQL; модули «Авторизация», «Ученики и зачисление», «Группы и расписание», «Оплаты», «Отчёты»; REST API `/api/schedule/`, `/api/courses/`                                                                                                                           |
| ЛР 9 — диаграмма классов | абстрактный класс `Person` (`Meta.abstract = True`), перечисление `Level`, методы `get_full_name`, `get_debt`, `get_schedule`, `is_free`, `add_student`, `get_students`, `add_payment`, `is_paid`, `reschedule`, `confirm`; композиции Group—Lesson и Enrollment—Payment (`on_delete=CASCADE`), ассоциации — `PROTECT` |

### Роли

- **Администратор** — все справочники и журналы, отчёты, резервная копия, стандартная панель Django `/admin/`.
- **Преподаватель** — своё расписание (может добавлять и переносить занятия только своих групп), свои группы и их
  ученики.
- **Ученик** — своё расписание, свои курсы с долгом, свои оплаты, каталог курсов (только просмотр).

Вход по логину и паролю (пароли хранятся в виде хешей, стандартная аутентификация Django).

### Проверки данных

- обязательные поля, формат телефона и e-mail;
- аудитория не занята в это время, преподаватель не ведёт другое занятие, группа помещается в аудиторию, занятие не
  раньше старта группы;
- ученик не зачисляется в одну группу дважды;
- оплата не превышает остаток долга и не раньше даты зачисления;
- удаление записи, на которую ссылаются другие, запрещено.

### Отчёты

Должники по оплате, поступления за период, наполняемость групп, нагрузка преподавателей, расписание на период. Любой
отчёт выгружается в CSV (открывается в Excel).

### Резервное копирование

- из интерфейса — JSON-файл со всеми данными; восстановление: `uv run python manage.py loaddata <файл>`;
- средствами PostgreSQL: `docker compose exec db pg_dump -U italian italian_school > backup.sql`.

## Структура

```
config/                 # настройки Django, корневые URL, WSGI
school/
├── models.py           # модели (ЛР 4, ЛР 9) и бизнес-проверки в clean()
├── entities.py         # реестр сущностей: поля форм, столбцы таблиц, доступ по ролям
├── views.py            # главная, универсальный CRUD, отчёты, бэкап, REST API
├── forms.py            # формы на основе моделей
├── reports.py          # построение отчётов
├── roles.py            # роли пользователей
├── admin.py            # панель администратора /admin/
├── templates/          # HTML-шаблоны (Bootstrap 5)
├── management/commands/seed_demo.py   # тестовые данные
├── migrations/         # схема БД
└── tests.py            # автотесты
Dockerfile, docker-compose.yml           # контейнеры web (gunicorn) и db (PostgreSQL 18)
```
